# Особистий кабінет клієнта

Сторінка `cabinet.html`. Працює у двох режимах:

| Режим | Коли | Дані |
|---|---|---|
| **Демо** | відкрити `cabinet.html?demo=1` (Supabase не підключено) | лише в браузері, нікуди не передаються |
| **Робочий** | заповнено `cabinet/config.js` | Supabase (безплатний тариф): Auth + Postgres + Row Level Security |

Без Supabase і без `?demo=1` відвідувач бачить сторінку «Кабінет готується до запуску».

## Що вміє кабінет

**Клієнт:** реєстрація/вхід/відновлення пароля · огляд · вантажі зі статусами, стрічкою кроків і історією · заявка на приймання · калькулятор · договори (реквізити з профілю → друк/PDF/Word → чернетка → «на підписання») · документи · відеоспостереження · чат із менеджером · сповіщення · профіль і зміна пароля.

**Менеджер:** огляд · активація/блокування клієнтів · видача доступу до камер · вантажі (статус, місце на складі, коментар для клієнта) · договори (позначити «Підписано») · додавання документів · керування камерами + журнал переглядів · чат.

**Статуси вантажу:** Заявка створена → Підтверджено → Прямує до хабу → Прибув на склад → Розвантаження → Прийнято, перевірено → На зберіганні → Сортування/пакування → Готово до відправлення → Передано в доставку → Доставлено (+ «Є зауваження», «Скасовано»).

## Підключення Supabase (≈15 хвилин)

1. Створіть проєкт на supabase.com (безплатний тариф).
2. **SQL Editor → New query**: вставте вміст `cabinet/supabase.sql` → **Run**.
3. **Project Settings → API**: скопіюйте **Project URL** і **anon public key** у `cabinet/config.js`.
   Ключ `service_role` НЕ вставляйте нікуди в сайт.
4. **Authentication → URL Configuration**: Site URL = адреса сайту (напр. `https://andriy2002-ops.github.io/tp-hub-landing/cabinet.html`), додайте її в Redirect URLs.
5. **Authentication → Providers → Email**: залиште підтвердження пошти ввімкненим.
6. Зареєструйтесь на сайті як клієнт, потім у SQL Editor виконайте (з вашою поштою):
   ```sql
   update public.profiles set role = 'manager', status = 'active' where email = 'ВАША_ПОШТА';
   ```
   Після входу ви побачите панель менеджера.
7. Нових клієнтів активуйте в розділі «Клієнти».

Сповіщення менеджеру в Telegram (реєстрація, заявка, договір, повідомлення) надсилаються через той самий Cloudflare Worker, що й форма (`notifyEndpoint` у `config.js`).

## Відеоспостереження: як зробити безпечно

Кабінет лише показує трансляцію за адресою, яку ви вкажете. Захист самого потоку лежить на відеосервері:

1. Камери/реєстратор віддають RTSP. Перетворіть його на HLS (`.m3u8`) або WebRTC сервером **go2rtc** або **MediaMTX** (безплатні) на будь-якому міні-ПК у складі.
2. Опублікуйте сервер назовні через **Cloudflare Tunnel** (безплатно), не відкриваючи порти роутера.
3. **Обов'язково** захистіть потік токеном або авторизацією (Cloudflare Access, перевірка підписаного токена у Worker). Інакше будь-хто з посиланням бачитиме камеру.
4. У розділі «Камери» додайте камеру: тип `HLS`, адреса `https://…/index.m3u8`. Доступ клієнтам видається в картці клієнта.

Права: клієнт бачить лише камери, які йому призначено, і лише з активним обліковим записом (це перевіряє база через RLS). Кожен перегляд пишеться в журнал, на відео накладається ім'я клієнта й час.

Юридично: камери фіксують людей, тож потрібні таблички про відеоспостереження, політика обробки персональних даних і договірна заборона передачі доступу третім особам. Узгодьте це з юристом.

## Безпека

- Усі таблиці закриті Row Level Security: клієнт бачить тільки свої записи, менеджер бачить усе. Роль і статус клієнт змінити не може (тригер у базі).
- Договори в базі зберігаються як дані (JSON), а текст генерується заново з екранування: збережений HTML ніколи не виводиться.
- Рекомендовано: увімкнути в Supabase CAPTCHA для реєстрації та ліміти запитів; для менеджерів використовувати окремий складний пароль.

## Обмеження поточної версії

- Файли документів додаються як **посилання** (Google Drive, Dropbox тощо), завантаження файлів напряму не реалізовано.
- Двофакторна автентифікація, команда з кількох користувачів на одну компанію й електронний підпис договору (Дія.Підпис) заплановані наступними етапами.
- Реальний режим (`supa.js`) написано за схемою `supabase.sql`, але перевірити його можна лише після створення вашого проєкту Supabase.
